# 제출 · 발표

## 1. 팀 저장소 구조

팀마다 저장소 하나 (과정 GitLab 또는 강사가 안내한 곳). **비공개**로 만들고 강사를 초대합니다.

```text
<팀 저장소>/
├── README.md                    # 팀 · 역할 · 실행 방법 · 웹훅 경로 · 시연 순서
├── AGENTS.md                    # CLI 코딩 에이전트 규칙 (09 문서)
├── docs/
│   ├── TOPIC.md                 # 주제 제안서 (80일차, 강사 승인)
│   ├── TEAM-CHARTER.md          # 팀 헌장 (80일차)
│   ├── WORKFLOW-DESIGN.md       # 산출물 1 · 노코드 워크플로우 설계서
│   ├── RAG-ARCHITECTURE.md      # 산출물 2 · RAG 아키텍처 설계서
│   ├── EXECUTION-RESULT.md      # 산출물 3 · 워크플로우 실행 결과서
│   ├── daily/                   # 데일리 기록 3장 (80 · 81 · 82)
│   └── images/                  # 실행 화면 캡처 (개인정보 · 키를 가린 것)
├── workflows/                   # n8n 워크플로우 JSON (키 없음)
│   ├── team1-support.json
│   ├── team1-index.json
│   └── team1-errors.json
├── knowledge/                   # 팀이 쓴 지식 문서 (다른 주제는 6개 이상)
├── data/                        # 다른 주제: users.json · records.json (가짜 데이터)
├── cases/common.json            # 다른 주제: 공통 시나리오를 옮긴 것
├── cases/team.json              # 팀 시나리오
├── requests/                    # 시연 · bench용 요청 파일
└── runs/                        # 시험 보고서 (flow.py test · bench의 JSON)
```

| 실행 가능 | 강사가 `README.md`대로 `flow.py push workflows/*.json` → `flow.py test cases/team.json`을 돌려 같은 결과가 나와야 함 |

### 제출 전 점검 (원본 요구 6절과 같음)

원본 [KSM-REQ.md](../Req/KSM-REQ.md) 6절 체크리스트 15개를 `docs/EXECUTION-RESULT.md` 끝에 그대로 붙여 체크합니다. 특히 공통 셋:

- [ ] 세 설계서 · 결과서의 내용이 실제 구현과 일치한다 (설계서의 노드 이름 = 워크플로우의 노드 이름).
- [ ] 예시 수치를 팀의 실제 측정값으로 교체했다 (`runs/` 보고서에서).
- [ ] 인증정보와 개인정보가 문서 · 로그 · 저장소에 노출되지 않았다.
