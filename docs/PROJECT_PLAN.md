# 내 안전 바구니

## 창고형 약국 직원용 반복 구매 안전 대응 헬프데스크

### 1. 기획 배경

창고형 약국은 영양제, 일반의약품, 바르는 연고 등 다양한 제품을 한 번에 비교하고 구매할 수 있다. 고객이 여러 제품을 구매하거나 다른 약국에서 유사 제품을 반복 구매하면 제품별 주의사항이나 중복 구매 가능성을 놓치기 쉽다.

이 프로젝트는 구매를 막거나 AI가 복용·사용 가능 여부를 판단하는 서비스가 아니다. 다량·반복 구매 상황에서 안전 확인 기회를 제공하고, 전문 판단이 필요한 문의는 약사에게 연결하는 내부 헬프데스크를 구현한다.

### 2. 사용자와 역할

| 사용자 | 역할 |
| --- | --- |
| 고객 | 창고형 약국에서 제품을 구매하거나 문의 |
| 매장 직원 | 제품 정보와 문의를 접수하고 약사 호출 |
| 책임약사 | 반복 구매·병용·이상 반응 등 전문 상담 필요 건 확인 |
| 운영 관리자 | 익명 처리된 이관 건수와 처리 현황 확인 |
| AI 워크플로우 | 개인정보 마스킹, 문서 검색, 규칙 분기, 이관·기록 자동화 |

### 3. 대표 시나리오

1. 매장 직원이 익명 고객 ID와 제품 코드를 텔레그램 봇에 입력한다.
2. 개인정보 마스킹 도구가 이름·전화번호 등 민감한 입력을 제거한다.
3. 제품 안내문 RAG 검색과 가상 약국 A·B·C 구매 이력 조회를 병렬로 실행한다.
4. 최근 반복 또는 유사 제품 구매 신호가 있으면 직원에게 약사 확인 안내를 제공한다.
5. 책임약사 전용 Discord 채널에 익명 상담 티켓을 전송한다.
6. 문의번호, 처리 버전, 이관 여부, 처리시간을 Google Sheets에 기록한다.

### 4. n8n 워크플로우

```text
Telegram Trigger
  -> 문의 정보 정리
  -> 개인정보 마스킹
  -> Canary 대상 확인
  -> [병렬] RAG 검색 + 구매 이력 조회
  -> Merge
  -> Switch: 일반 안내 / 반복 구매 / 약사 이관
  -> Telegram 직원 안내 + Discord 약사 알림
  -> Google Sheets 실행 로그 저장
```

### 5. 핵심 규칙

| 상황 | 시스템 처리 |
| --- | --- |
| 제품 보관법·라벨상 주의사항 문의 | RAG 기반 직원용 표준 안내문 제공 |
| 최근 7일 내 같은 제품군 반복 구매 | 약사 확인 권장 알림 |
| 여러 외용제를 함께 사용하려는 문의 | 자동 판단 없이 책임약사 이관 |
| 처방약 복용·이상 반응 언급 | 즉시 책임약사 이관 |
| 제품명이 불명확함 | 바코드·제품명 재확인 요청 |
| Discord 알림 실패 | Sheets에 약사 이관 대기 상태 저장 |

`최근 7일 내 2회 구매`는 의료적 금지 기준이 아니라, 프로젝트 시연용 안전 확인 규칙이다.

### 6. 목데이터 범위

| 데이터 | 구성 |
| --- | --- |
| 제품 | 가상 일반의약품·외용제 4종, 건강기능식품 2종 |
| RAG 문서 | 제품별 보관법·주의사항·약사 이관 기준 6~8개 |
| 구매 이력 | 가상 약국 A·B·C의 익명 구매 기록 20건 |
| 직원 | `STAFF-001`~`STAFF-010` |

실제 고객 이름, 연락처, 질환명, 처방약명, 사진은 사용하지 않는다.

### 7. Canary 배포

새 반복 구매 규칙은 전 직원에게 즉시 적용하지 않는다. `STAFF-001`~`STAFF-008`은 기존 V1 흐름을 사용하고, `STAFF-009`~`STAFF-010`은 반복 구매 규칙이 강화된 V2 흐름을 사용한다. 두 흐름의 처리시간, 오류 여부, 약사 이관 비율을 비교한 뒤 안정적인 규칙을 전체에 확대한다.

### 8. 수업 도구 활용

| 도구 | 활용 |
| --- | --- |
| agy·n8n | 워크플로우 JSON 관리·실행 |
| tflow | 워크플로우 구조 시각화 |

### 9. 3일 계획

| 일정 | 작업 |
| --- | --- |
| 1일 차 | 가상 제품·FAQ·구매 이력 작성, Telegram·Sheets 연결 |
| 2일 차 | n8n 분기, RAG 검색, 반복 구매 규칙, Discord 이관 구현 |
| 3일 차 | Canary·실패 테스트, 실행 결과서와 발표 자료 작성 |
