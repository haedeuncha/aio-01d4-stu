# 인사(HR) 문의 창구 SPEC

> 요청 (직원의 말): "연차 몇 개 남았는지 알려 주고, 11월 6일 금요일에 연차 쓸게. 그리고 병가 쓰려면 진단서 필요해?"
> 한 문장에 업무가 여럿 섞여 오면 나눠서 각 담당 Agent가 처리하고, 한 번에 답한다.

## 1. 요구 (확인할 수 있게)

| 번호 | 요구 | 요청의 어느 말 | 확인 방법 (`cases/` 파일 · 케이스 이름 · 값) | 됐다 |
| --- | --- | --- | --- | --- |
| R1 | 한 문장을 업무로 나눠 순서대로 `{count, results[], reply}`로 답한다 | 문장 전체 | `a3-hr.json` "복합 3개" → `count` 3, `results.0~2` 순서 = 조회 · 신청 · 규정 | ☑ |
| R2 | 남은 연차를 알려 준다 (총 · 사용 · 남음) | "몇 개 남았는지" | `a3-hr-agents.json` "연차 · 본인 조회" → `remaining` 9 / 라우터 `results.0.answer`에 "9일" | ☑ |
| R3 | 휴가 신청을 접수하고 접수 번호 · 신청 후 남은 연차를 준다 | "11월 6일 연차 쓸게" | "휴가 · 접수" → `접수 완료`, `days` 1, `remaining_after` 8 | ☑ |
| R4 | 규정 질문은 규정집으로만 답하고 근거 번호를 붙인다 | "진단서 필요해?" | "HR 규정 · 병가 진단서" → `sources`에 HR-3, 답에 "진단서" | ☑ |
| R5 | 빈 요청은 400과 보낼 모양 예시(`hint`) | — | "빈 요청 · 400" | ☑ |
| R6 | 맡을 수 없는 일은 지어내지 않고 담당자 연결 | — | "범위 밖 · 담당자 연결"(월급), "규정에 없는 질문"(육아휴직) | ☑ |

## 2. 숨은 요구

| 숨은 요구 | 왜 | 확인 |
| --- | --- | --- |
| 남의 연차는 숫자를 보여 주지 않는다 | 개인 정보 (67일차 IT Agent 규칙과 같음) | "남의 연차 숨김" → `담당자 연결`, `reply`에 "0.5일"·"14.5" 없음 |
| `user`는 웹훅 입력에서만, 권한 검사는 Agent 안 Code에서 | LLM · 라우터를 믿지 않음 | `a3-hr-balance.json`의 `Look up balance` |
| 남은 연차보다 많이 신청하면 거절 | 규칙은 Code가 판단 | "잔여 부족 거절"(이준호 0.5일) |
| 3일 전까지 신청(HR-1), 주말은 빼고 계산 | 규정 | "휴가 · 3일 전 규칙", "휴가 · 주말", "오후 반차 접수"(0.5일) |
| 날짜가 없으면 지어내지 않고 `입력 필요` + 예시 | LLM이 오늘 날짜를 지어낸 적 있음 | "날짜 없음 · 입력 필요" (5회 반복 통과) |
| 담당 Agent가 꺼져도 다른 업무는 처리 | 한 곳 장애가 전체를 멈추면 안 됨 | HTTP `neverError` + 결과 노드의 기본값 |

## 3. 범위 밖

실제 인사 시스템 연결 · 승인 처리(팀장 승인은 "접수"까지만), 급여 · 복지 문의, 공휴일 달력, 신청 내역 저장(연습 데이터는 고정).

## 4. 만드는 순서 (그리고 이유)

1. Agent 3개 (`a3-hr-balance` → `a3-hr-leave` → `a3-hr-policy`): 라우터가 부를 계약을 먼저 고정하고 단독으로 테스트
2. 라우터 `a3-hr`: 업무 나누기(LLM) → 검사(Code) → Switch → Agent 호출 → 모으기
3. 반복 테스트(× 3)로 LLM 흔들림 확인 → 실패를 규칙으로 고침 (README 6절)
