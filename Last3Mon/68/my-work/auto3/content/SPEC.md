# 마케팅 콘텐츠 제작 SPEC

> 요청 (마케터의 말): "신제품 소개글 써 주고, 인스타랑 X용으로 줄여 줘. 11월 2일에 올리게 일정도 잡아 줘."
> 요청 본문에 제품 정보 `product: {name, price, features}`가 함께 온다.
> HR · 출장과 달리 **업무 사이에 순서가 있다**: SNS 글은 소개글이 나와야 만들 수 있다.

## 1. 요구 (확인할 수 있게)

| 번호 | 요구 | 요청의 어느 말 | 확인 방법 (`cases/` 파일 · 케이스 이름 · 값) | 됐다 |
| --- | --- | --- | --- | --- |
| R1 | 업무를 나눠 **소개글 → SNS → 일정** 차례로 처리하고 `{count, results[], reply}`로 답한다 | 문장 전체 | `a3-content.json` "복합 3개" → `count` 3, agent 순서 a3-copy · a3-sns | ☑ |
| R2 | 제품 정보만으로 소개글을 쓴다 (제품 이름 포함) | "소개글 써 주고" | "소개글 · 이름과 가격" → `text`에 "루미 무선 이어폰" | ☑ |
| R3 | 소개글을 채널별 SNS 글로 줄인다 (글자 수 · 해시태그 한도) | "인스타랑 X용으로" | "SNS · 인스타·X" → `posts.0` instagram, `posts.1` x, `limit` 140 | ☑ |
| R4 | 게시 일정을 등록하고 겹치는 공용 일정을 알려 준다 | "11월 2일에 올리게" | "복합 3개" → 답에 "신제품 발표" | ☑ |
| R5 | 빈 요청은 400과 `hint` | — | "빈 요청 · 400" | ☑ |
| R6 | 맡을 수 없는 일은 담당자 연결 | — | "범위 밖 · 광고비" | ☑ |

## 2. 숨은 요구

| 숨은 요구 | 왜 | 확인 |
| --- | --- | --- |
| 입력에 없는 가격 · 숫자 · 할인을 쓰지 않는다 (Code가 숫자를 입력과 비교, 어기면 입력만으로 만든 안전한 글) | 광고에 틀린 가격이 나가면 사고 | "소개글 · 가격 지어내지 않음", "가격 없으면 가격 안 씀" → "000원" · "할인" · "%" 없음 |
| SNS에 보내는 글은 LLM이 아니라 **소개글 Agent의 응답**에서 가져온다 | 앞 단계 결과를 그대로 이어야 함 | `Call SNS agent`의 본문 `copy_text` |
| X 140자 · 인스타 300자 · 링크드인 400자, 해시태그 수는 Code가 지킨다 | LLM은 글자 수를 잘 못 셈 | `a3-sns.json`의 `Check posts`, 답에 `[x 66/140자]` |
| 앞 단계가 실패하면 뒤 단계를 부르지 않고 이유를 알려 준다 | 빈 글로 SNS를 만들면 안 됨 | `Save copy`가 `run.sns`를 끔 |
| 제품 정보가 없으면 지어내지 않고 `입력 필요` + 보낼 모양 예시 | 제품을 LLM이 만들면 안 됨 | "제품 정보 없음 · 입력 필요" |
| 원문(`text`)만 있으면 소개글 없이 SNS만 | 자주 쓰는 경우 | "SNS만 · 원문 있음" → `count` 1 |
| 날짜가 없으면 `입력 필요`, LLM이 업무를 0개로 줘도 낱말 규칙으로 다시 찾는다 | "게시 일정 잡아 줘"에서 0개가 나온 실패가 있었음 | "게시 날짜 없음 · 입력 필요" (5회 반복 통과) |
| 일정 Agent는 이 폴더 전용(`a3-content-schedule`) | 과제를 따로 내기 위해 | 이 폴더 파일만 push해도 동작 |

## 3. 범위 밖

이미지 · 영상 제작, 실제 SNS 게시, 광고비 집행, 맞춤법 검사기 연결.

## 4. 만드는 순서 (그리고 이유)

1. `a3-content-schedule` (Code만) → `a3-copy`(LLM + 숫자 검사) → `a3-sns`(LLM + 글자 수 검사)
2. 라우터 `a3-content`: Switch 대신 **If 차례 흐름** (`Need copy?` → `Need SNS?` → `Need schedule?`), 결과는 `results`에 채워 다음 단계로 넘김
3. 반복 테스트 → 실패를 규칙으로 고침 (README 6절)
