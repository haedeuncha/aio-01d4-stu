# 출장 준비 비서 SPEC

> 요청 (직원의 말): "11월 12일부터 14일까지 부산 출장 가. 숙소는 하루 얼마까지 돼? 출장비 신청하고 일정도 잡아 줘."
> 출장 정보(도시 · 날짜)를 한 번 뽑아 규정 · 출장비 · 일정 세 업무에 똑같이 쓰고, 한 번에 답한다.

## 1. 요구 (확인할 수 있게)

| 번호 | 요구 | 요청의 어느 말 | 확인 방법 (`cases/` 파일 · 케이스 이름 · 값) | 됐다 |
| --- | --- | --- | --- | --- |
| R1 | 한 문장을 업무로 나눠 순서대로 `{count, results[], reply}`로 답한다 | 문장 전체 | `a3-trip.json` "복합 3개" → `count` 3, 규정 · 출장비 · 일정 순서 | ☑ |
| R2 | 도시별 숙박 한도를 규정대로 알려 준다 | "숙소는 하루 얼마까지" | "출장 규정 · 부산 숙박" → 답에 "100,000" 또는 "10만", 근거 TR-1 | ☑ |
| R3 | 출장비를 계산해 접수하고 계산 내역을 보여 준다 | "출장비 신청하고" | "출장비 · 부산 2박 3일" → `amount` 290000 / "서울 1박 2일" → 180000 | ☑ |
| R4 | 출장 일정을 등록하고 같은 기간 일정을 알려 준다 | "일정도 잡아 줘" | "복합 3개" → `results.2.route` 등록 완료, 답에 ⚠ 전사 워크숍 | ☑ |
| R5 | 빈 요청은 400과 `hint` | — | "빈 요청 · 400" | ☑ |
| R6 | 맡을 수 없는 일은 담당자 연결 | — | "범위 밖 · 기차표 예매" | ☑ |

## 2. 숨은 요구

| 숨은 요구 | 왜 | 확인 |
| --- | --- | --- |
| 금액은 LLM이 아니라 Code가 규정표로 계산 (숙박 × 박 + 일비 × 일 + 교통) | LLM은 계산 · 숫자를 틀릴 수 있음 | `a3-trip-expense.json`의 `Calculate and accept`, 반복해도 같은 금액 |
| 7박 초과 · 100만 원 초과는 팀장 결재(TR-4) → 담당자 연결 | 규정 | "10박 · 팀장 결재" |
| 도시 · 날짜는 **한 번만** 뽑아 세 업무에 같이 붙인다 | 업무마다 다르게 뽑으면 답이 서로 어긋남 | `Parse tasks`의 `trip` |
| 날짜가 없으면 지어내지 않고 `입력 필요` | LLM이 오늘 날짜를 지어내 30,000원으로 접수한 실패가 있었음 | "날짜 없음 · 입력 필요", "일정 날짜 없음 · 입력 필요" |
| 지난 날짜 일정은 거절, 남의 개인 일정은 겹침 알림에도 보이지 않음 | 개인 정보 · 잘못된 등록 방지 | "지난 날짜 일정 · 거절", "일정 · 남의 개인 일정 숨김" |
| 일정 Agent가 꺼져도 규정 · 출장비는 정상 | 장애 격리 | `a3-trip-down.json` (off → test → push) |
| 과제를 따로 낼 수 있게 일정 Agent를 이 폴더 전용(`a3-trip-schedule`)으로 | 다른 과제와 섞이지 않게 | 이 폴더 파일만 push해도 동작 |

## 3. 범위 밖

기차 · 숙소 예매, 실제 결재 시스템, 교통비 자동 조회(모르면 0원으로 접수 후 영수증 정산), 해외 출장.

## 4. 만드는 순서 (그리고 이유)

1. `a3-trip-schedule` (LLM 없이 Code만, 가장 쉬움) → `a3-trip-expense`(계산 규칙) → `a3-trip-policy`(규정 찾기 + LLM 설명)
2. 라우터 `a3-trip` (HR 라우터와 같은 모양 + 출장 정보 한 번 뽑기)
3. 반복 테스트 · Agent 끈 상태 테스트 → 실패를 규칙으로 고침 (README 6절)
