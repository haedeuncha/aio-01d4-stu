## 2. 구현 및 실패 수정

- Lab 1에서 sources 누락과 거절 문구의 금지 표현으로 과제 테스트가 실패했던 기록을 확인했습니다. Tool 응답에서 출처를 추출하고 안전한 거절 문구를 반환하도록 수정했습니다.
- 67일차 최종본은 FAQ 검색과 본인 접수 조회를 구분합니다. requester는 질문에서 AI가 추론하지 않고 body.user에서 전달합니다. 접수 조회에 user가 없으면 Tool 실행 전 거절합니다.
- 403/404 및 검색 결과 없음은 자동 답변 검증을 통과시키지 않습니다. 거절 시 answer와 draft에 남의 접수 내용이 포함되지 않도록 처리했습니다.
- 추가 시나리오 8개는 이번 3회 반복 실행에서 모두 통과했습니다. 이번 실행에서 추가 테스트 실패는 재현되지 않았습니다. 학습자가 직접 원인을 적었다고 기록하지 않았습니다.
- 66일차는 명시적인 참석자 줄에서만 참석자를 추출하고, 누락된 담당자·기한은 미정으로 표시합니다. 회의록 안의 AI 대상 지시는 따르지 않도록 설정했습니다.
- 기존 제공 테스트의 기대값은 변경하지 않았습니다. 66일차 통합 테스트는 원래 기대값을 복사하고 요청 파일을 본문으로 펼쳐 작성했습니다.

## 4. 게시 상태 및 구성

- 6개 워크플로우의 이름·설명·노드·연결이 로컬 최종본과 일치하고 최신 버전이 게시됐음을 확인했습니다.
- 65일차는 실습 4개를 각각 분리했습니다. 66·67일차는 강의의 누적 수정 방식을 따라 각각 Lab 1~3 최종 기능을 하나로 구성했습니다. Lab별 독립 워크플로우로 분리한 상태는 아닙니다.
- 게시 내역: `runs/course-published-workflows.json`.
- 실습의 user는 요청 본문의 값입니다. 실제 서비스에서는 인증된 사용자 정보와 연결해야 합니다.
- 담당자 연결/담당자 확인은 결과 분류이며 실제 메일 발송이나 접수 시스템 등록을 수행하지 않습니다.
