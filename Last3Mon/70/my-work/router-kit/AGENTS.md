# AGENTS.md · router-kit 공통 규칙

`Last3Mon/70/AGENTS.md`(70일차 규칙)를 그대로 따르고, 이 폴더에서는 아래를 더한다.

## 기준 문서

- `SPEC.md`: 무엇을 만들까 (R1~R6). 사람 허락 없이 고치지 않는다.
- `imp-plan.md`: 어떤 순서로. **계속 바꾸는 문서**다. 단계가 끝나면 "진행 상태" 표를 고치고, 계획과 달라진 점은 "변경 기록"에 날짜 · 단계 · 바꾼 것 · 왜를 한 줄 적는다. 단계를 빼거나 순서를 바꾸는 큰 변경은 사람에게 먼저 묻는다.
- `DESIGN.md`: 비교 표 · 변수 표 · 모듈 계약 · 영향 표.

## 작업 순서

1. 요청이 SPEC의 어느 요구(R1~R6)인지, 어떻게 확인할지 먼저 말한다.
2. **요청받은 단계만** 한다.
3. 워크플로우: `check` → (허락받았으면) `push` → `test --repeat 3`. 모듈을 고쳤으면 **영향 표의 테스트를 모두** 다시 돈다.
4. `imp-plan.md` 진행 상태 · 변경 기록을 고치고, 바꾼 파일 · 테스트 결과 · 사람이 실행할 명령을 보고한다.

## 이름 규칙 (다른 실습과 섞이지 않게)

| 무엇 | 규칙 | 예 |
| --- | --- | --- |
| 워크플로우 파일 | `my-work/router-kit/rk-<이름>.json` | `rk-hr.json` |
| 웹훅 경로 | `rk-<이름>` | `rk-hr` |
| 워크플로우 이름 | n8n 목록 규칙 `70-<번호> · <이모지> …` (라우터는 값 파일의 `name`) | `70-7 · 🧭 router-kit · HR 라우터 (원본)`, `70-9 · 🧩 모듈 · 답장 만들기 v1 (modBuildReply01)` |
| 모듈 | 파일에 `id` 직접, `mod<이름><두 자리 버전>` | `modBuildReply01` |
| 테스트 | `my-work/router-kit/cases/rk-<이름>.json` | `cases/rk-hr.json` |

- 68일차 `a3-*` 워크플로우(과제 제출본)는 고치지 않는다. 라우터는 이미 있는 `a3-*` Agent를 HTTP로 부르기만 한다.

## 템플릿 규칙

- 템플릿 변수는 `[[ 이름 ]]`. n8n 표현식 `{{ … }}`, `$json`, `$('노드')`는 템플릿이 건드리지 않는다.
- 렌더는 JSON을 **읽은 뒤** 글자 값 안의 `[[ ]]`만 바꾼다 (JSON 글자를 통째로 바꾸지 않음 → 따옴표 · 줄바꿈이 안전).
- 노드 이름 · 연결은 변수로 두지 않는다. 갈래 수를 바꾸는 것은 새 템플릿 버전(v2).
- 렌더한 파일을 손으로 고치지 않는다. 고칠 곳이 있으면 템플릿이나 값 파일을 고친다.

## 하지 말 것

- `tools/`, `requests/`, `reference/`, `samples/`, `Last3Mon/70/AGENTS.md`를 고치지 않는다.
- 모듈의 입력 · 결과 이름을 바꾸지 않는다 (새 id로 새 버전).
- 테스트를 통과시키려고 기대값을 바꾸지 않는다.
- 마크다운 문서에 HTML 태그를 쓰지 않는다 (mermaid 글자 안 포함).
