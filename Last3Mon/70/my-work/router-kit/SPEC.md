# router-kit SPEC · 멀티 Agent 라우터 템플릿

> 68일차에 HR · 출장 라우터를 손으로 하나씩 만들었다. 둘은 모양이 같고 업무 유형 · Agent 주소 · 프롬프트만 다르다.
> 70일차 방식(같은 것은 모듈로, 다른 것은 설정 · 변수로, 바꿀 때는 버전으로)으로 **라우터를 찍어 내는 템플릿**을 만든다.

## 1. 요구 (확인할 수 있게)

| 번호 | 요구 | 확인 방법 (파일 · 숫자 · 명령) | 됐다 |
| --- | --- | --- | --- |
| R1 | **기준 라우터** `rk-hr`: 68일차 `a3-hr`와 같은 동작을 하는 원본을 이 폴더에 둔다 (68일차 과제 파일은 건드리지 않음) | `cases/rk-hr.json` 7개 × 3 통과 | ☑ |
| R2 | **답장 모듈** `modBuildReply01`: 입력 `user`, `results` → `{count, results, reply}`. 기준 라우터의 `Build reply`를 모듈 호출로 바꾼다 | `cases/rk-reply.json`(모듈 시험용 웹훅) 통과 · `cases/rk-hr.json` 그대로 7 × 3 (회귀) | ☑ |
| R3 | **템플릿 폴더** `templates/n8n-router/`: `template.yaml`(변수 이름 · 설명 · 종류 · 기본값)과 `router.json` · `cases.json`. 변수 표시는 `[[ 이름 ]]` | 변수 목록이 `DESIGN.md` 2절 비교 표와 같다 | ☑ |

## 2. 숨은 요구

| 숨은 요구 | 왜 |
| --- | --- |
| 템플릿 변수 `[[ name ]]`과 n8n 표현식 `{{ $json… }}`이 한 파일에 섞여도 n8n 표현식은 절대 바뀌지 않는다 | 70일차 VIBE-Q-TKIT에서 가장 까다로운 곳 |
| 변수 값에 따옴표 · 줄바꿈 · 한글이 있어도 JSON이 깨지지 않는다 (JSON을 읽은 뒤 글자 값 안에서만 바꾼다) | 프롬프트는 여러 줄 · 따옴표가 많다 |
| 노드 이름 · 연결(흐름)은 변수로 두지 않는다. 갈래는 `Lane settings` 표(B안)라서 흐름이 바뀌지 않는다 | 흐름을 바꾸는 변수는 템플릿을 망가뜨리기 쉽다 (70일차 자료) |
| 변수 값을 검사한다: 필수 칸 비움, 웹훅 경로에 빈칸 · 대문자, 이미 쓰는 웹훅 경로 | 잘못 찍은 라우터가 다른 라우터를 막지 않게 |
| 모듈의 입력 · 결과 이름은 바꾸지 않는다. 바꿔야 하면 새 id | 70일차 AGENTS.md 9절 |
| `user`, 금액 같은 값은 LLM이 아니라 웹훅 입력 · Code에서 (68일차 규칙 그대로) | 템플릿으로 찍어도 규칙이 사라지면 안 됨 |

## 3. 범위 밖

- 갈래(업무 종류)마다 다른 흐름 (B안: 모든 갈래가 같은 `Call agent` 하나를 지나고, 다른 점은 `Lane settings` 표에만)
- 새 Agent 만들기 (찍어 낸 라우터는 이미 있는 Agent를 부른다)
- tkit TUI 화면 (렌더 엔진 `render.py`까지가 이번 범위, 화면은 다음)

## 4. 만드는 순서 (이유)

`imp-plan.md` 참고. 잘 도는 원본(R1) → 공통 부분을 모듈로(R2) → 다른 부분을 변수로(R3) → 다시 찍어 원본과 비교(R4) → 새 업무(R5) → 버전(R6).
원본이 테스트를 통과한 상태에서 하나씩 바꿔야, 틀어졌을 때 어느 단계 탓인지 바로 안다.
