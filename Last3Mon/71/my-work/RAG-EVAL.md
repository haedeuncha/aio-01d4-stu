- 섹션에서 answer@1을 틀린 질문 (둘 다 doc@1 ✔ · answer@3 ✔ → 맞는 문서의 다른 섹션이 1등):
  - 회사를 그만두면 노트북은 …? → 1등 `1. 지급과 교체` 0.461, 답 "5영업일"은 2등 `3. 반납` 0.446 (차이 0.015). 1등 섹션에 질문 낱말 "노트북"이 있음.
  - 고객 정보가 밖으로 샌 것 같아요 → 1등 `2. 이용과 보관` 0.395, 답 "1시간"은 2등 `3. 유출 대응` 0.375 (차이 0.02). 1등에 "고객", 답 섹션은 "유출".
- 200자 (17청크): 섹션이 대부분 200자보다 짧아 한 조각에 여러 섹션이 섞인다. "개인정보 파일을 거래처에 메일로"가 `privacy`로 가고 답 "암호"가 3등 안에서도 빠짐, "바이러스"의 "랜선"이 1등에서 빠짐.
- 400자 (9청크): 문서가 거의 통째 → 1등 문서는 자주 틀리지만(21/24) 청크가 커서 3등 안에는 답이 다 있음(24/24). 대신 LLM에게 관련 없는 글이 많이 간다.
- answer@1에서 틀린 질문 (숫자만 보면 놓치는 것, 교안 3.3절):

  | 설정 | answer@1 틀린 질문 |
  | --- | --- |
  | 섹션 | 퇴사 노트북 (5영업일), 고객 정보 유출 (1시간) |
  | 200자 | 퇴사 노트북, 바이러스 (랜선), 개인정보 파일 메일 (암호) |
  | 400자 | 로그인 여러 번 틀림 (30분), 개인 휴대폰 메일 (MDM), 개인정보 파일 메일 (암호), 화면 잠금 (5분) |
  | 섹션 + 다시 쓰기 | 없음 (3번 모두) |

- 교안(10/18 · 10/22)과 비교: 섹션 25청크 24 · 22 · 24는 **같다**. 200자 · 400자는 청크 수부터 다르다 (교안 20 · 12, 내 것 17 · 9). 참고 워크플로우(`reference/lab01-example2-index.json`)는 글자 수로 자를 때 **20%씩 겹치게**(`step = size - size/5`) 자르고, 내 `Make chunks`는 겹치지 않게 자른다. 겹침이 없으면 경계에서 문장이 더 잘리고 청크도 적어 200자 23 · 21 · 23, 400자 21 · 20 · 24로 교안보다 조금 낮다. 바꾼 것 하나(청크 크기) 안에 "겹침"이라는 설정이 숨어 있었던 것 — 실험 기록에 함께 적어야 하는 값.
- 400자 "화면 잠금"은 교안처럼 섹션이 섞여 틀림 (원격근무 문서 섹션 셋이 한 청크).
- 결론: 섹션이 짧고 주제별로 나뉜 우리 문서에는 **섹션 청크가 세 지표 모두 가장 좋다**. 섹션으로 되돌림.
- 관련도 기준 0.33 (`lab03-threshold`, 섹션): **10/10**. 규정 질문 최저 0.464(노트북), 규정 밖 최고 0.261(연봉) → 0.20 벌어짐. 단 "점수는 높은데 답이 없는" VPN 0.463은 노트북 0.464와 같아 **기준값을 올려도 거를 수 없다** (올리면 노트북 질문이 먼저 떨어짐) → 답 검사가 필요한 이유.

## 5. 어려운 질문 (Lab 03 과제)

검색을 고치기 전에 질문의 기대 문서와 답 문구가 실제 규정 원문에 있는지 다시 확인한다. 실행 전·후 점수와 새로 실패한 기존 질문을 함께 기록한다.

- 테스트: `cases/my-cases.json` 12문항 (직원 말투, 답이 있는 문서만, 기대 `hits.0.source`). 모두 `--repeat 3`.
- 고른 개선: **질문 다시 쓰기** (`search.json`에 AI Agent `Rewrite query`를 검색 앞에). 이유: 실패 셋이 모두 "질문 낱말 ≠ 규정 낱말"(챗GPT · 제미나이 · 카톡 → 규정은 "생성형 AI 서비스" · "소프트웨어 설치")이라 낱말을 바꾸는 개선이 원인에 맞음. 낱말표(Code)는 내 질문 낱말을 하나하나 넣게 되어 맞추기가 되기 쉬움.
